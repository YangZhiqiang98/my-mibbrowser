# Hook Guidelines

> How hooks are used in this project.

---

## Overview

The project uses standard React hooks plus Zustand's `useStore` selector pattern. No custom hooks exist yet, but the patterns below should guide new hook creation.

---

## Built-in Hook Usage

- **`useEffect`**: For IPC calls on mount (loading profiles, loading MIB tree).
- **`useState`**: For local-only UI state (form inputs, toggle visibility).
- **`useCallback` / `useMemo`**: Use when needed for performance, not by default.

---

## Zustand Selector Pattern

Access store state with selectors — not by destructuring the entire store:

```typescript
// CORRECT: Select only what the component needs
const config = useAppStore((s) => s.snmpConfig)
const setConfig = useAppStore((s) => s.setSnmpConfig)

// WRONG: Destructuring entire store causes unnecessary re-renders
const { snmpConfig, setSnmpConfig, ... } = useAppStore()
```

---

## Custom Hook Patterns

When creating custom hooks:

- Name with `use` prefix: `useMibTree`, `useSnmpQuery`.
- Keep hooks focused on a single concern.
- Hooks can call `window.api.*` for IPC communication.
- Return `[state, actions]` tuple or an object with named fields.

```typescript
function useSnmpQuery() {
  const [loading, setLoading] = useState(false)
  const [result, setResult] = useState<SnmpResult | null>(null)

  const execute = async (config: SnmpConfig, oid: string) => {
    setLoading(true)
    const res = await window.api.snmp.get(config, [oid])
    setResult(res)
    setLoading(false)
  }

  return { loading, result, execute }
}
```

---

## Data Fetching

- IPC calls go through `window.api.*` (the preload bridge).
- No React Query / SWR — direct async calls in `useEffect` or event handlers.
- Loading states managed in Zustand store (`isQuerying`).

---

## Naming Conventions

- Custom hooks: `use` prefix + PascalCase domain: `useSnmpQuery`, `useMibTree`
- Store hooks: generated by Zustand, accessed via `useAppStore`
